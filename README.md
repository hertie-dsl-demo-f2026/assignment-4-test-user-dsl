# Hackathon showcase

This is a sprint, not a term project: in a short, compressed window you will pick a small
data problem, build something that actually runs, and show it off.

## Task

Choose a dataset and a question you can make real progress on quickly - better a small,
working end-to-end pipeline than an ambitious one that only half-runs by the deadline.
Spend the first stretch of time getting something crude working front to back before you
polish any single part of it; a rough baseline that produces an answer beats a
beautifully engineered feature pipeline with nothing at the end of it.

Because this repository is public from the day it is handed out, treat every commit as
something a stranger could read. Keep the write-up short and honest about what worked and
what did not; a hackathon project that admits its limitations is more convincing than one
that oversells a result nobody can reproduce.

Suggested approach:

- Pick a problem you can scope down to something finishable.
- Get a crude end-to-end version working before improving any one part.
- Keep a short running log of decisions and dead ends as you go.
- Prepare a brief demo: what it does, what it does not, and why.

## What to submit

Push your notebook or code, and a short write-up, to `main`. This repository is public
from day one, so commit nothing private or sensitive - no credentials, no personal data,
nothing you would not want indexed.

## Grading

- Prototype (40%): does it run end to end, and does it answer the question you set yourself?
- Demo (30%): can you explain what you built and why, clearly and honestly?
- Write-up (30%): a short, accurate account of the approach, its limits and what you would
  do with more time.
